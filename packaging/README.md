# System Packaging Channels for pi2d

This directory contains the packaging templates and documentation for distributing
`pi2d` across system-level package channels.

## Distribution Channels

Every channel distributes the prebuilt single-binary artifacts built from Bun, bundling
both the CLI launcher and the React web console.

| Channel | Target Audience | User Installation Command |
|---|---|---|
| **curl installer** | Generic Linux & macOS | `curl -fsSL https://raw.githubusercontent.com/zgs225/pi2d/main/scripts/install.sh \| sh` |
| **Homebrew tap** | macOS & Linux (Homebrew) | `brew install zgs225/tap/pi2d` |
| **Arch AUR (`-bin`)** | Arch Linux / Manjaro / EndeavourOS | `paru -S pi2d-bin` (or `yay -S pi2d-bin`) |

### Shared Tarball Layout Contract

All distribution channels consume the release tarballs published on GitHub Releases:
```
https://github.com/zgs225/pi2d/releases/download/v<VERSION>/pi2d-<VERSION>-<target>.tar.gz
```
Where `<target>` is one of:
- `linux-x64`
- `linux-arm64`
- `linux-x64-musl`
- `linux-arm64-musl`
- `darwin-x64`
- `darwin-arm64`

Each release tarball unpacks with the following layout at its root:
```
bin/
  pi2
share/
  pi2d/
    web/
      dist/
        index.html
        ...
LICENSE
```

**Crucial layout rule**: `pi2` resolves its web console assets at runtime via:
```typescript
resolve(dirname(executablePath()), "..", "share", "pi2d", "web", "dist")
```
(defined in `src/core/install.ts`).

Every channel must install `bin/pi2` into `<prefix>/bin` and `share/pi2d/web/dist` into
`<prefix>/share/pi2d/web/dist` under the same prefix (e.g. `/usr/local`, `/opt/homebrew`,
or `/usr`).

## Files & Templates

- `packaging/homebrew/pi2d.rb.in`: plain template for Homebrew formula `pi2d.rb`. Contains
  platform stanzas (`on_macos`, `on_linux` with `on_arm` and `on_intel`) and `install` /
  `test` / `caveats` blocks. Linux stanzas target standard glibc releases.
- `packaging/aur/PKGBUILD.in`: plain template for the Arch Linux AUR package `pi2d-bin`.
  Uses `options=('!strip')` because Bun binaries embed bytecode/metadata that strip damages.
  Targets x86_64 and aarch64 glibc tarballs (Alpine/musl tarballs are omitted for Arch).
- `scripts/update-packaging.sh`: deterministic generator script substituting placeholders
  and validating checksums.

## One-Time Bootstrap

### 1. Homebrew Tap (`zgs225/homebrew-tap`)

1. Create a public repository on GitHub named `zgs225/homebrew-tap`.
2. Create the `Formula/` directory in that repository.
3. Place the initial `Formula/pi2d.rb` generated by `scripts/update-packaging.sh`.
4. Commit and push to `main`.
5. Users can now install with:
   ```bash
   brew install zgs225/tap/pi2d
   ```

### 2. Arch Linux AUR (`pi2d-bin`)

1. Register an account on [aur.archlinux.org](https://aur.archlinux.org) and add your SSH public key.
2. Initialize the AUR package repository locally:
   ```bash
   git clone ssh://aur@aur.archlinux.org/pi2d-bin.git
   ```
3. Generate the initial `PKGBUILD` and `.SRCINFO` using `scripts/update-packaging.sh`.
4. Copy `PKGBUILD` and `.SRCINFO` into the cloned `pi2d-bin` directory, commit, and push:
   ```bash
   git add PKGBUILD .SRCINFO
   git commit -m "feat: initial release"
   git push origin master
   ```
5. Set up an SSH private key as a repository secret (e.g. `AUR_SSH_KEY`) in GitHub repository
   `zgs225/pi2d` so the release workflow can push updates to the AUR repository.

## Release-Time Bump Flow

During a release (via GitHub Actions workflow when a version tag `vX.Y.Z` is pushed):
1. The release job builds binary tarballs for all 6 targets and generates `SHA256SUMS`.
2. The packaging step executes:
   ```bash
   bash scripts/update-packaging.sh --version <VERSION> --checksums dist-bin/SHA256SUMS --out build/packaging
   ```
3. The generated `build/packaging/pi2d.rb` is committed and pushed to `Formula/pi2d.rb` in
   the `zgs225/homebrew-tap` repository.
4. The generated `build/packaging/PKGBUILD` and `build/packaging/.SRCINFO` are committed
   and pushed to the `pi2d-bin` AUR repository.

## Local Regeneration

You can regenerate or preview packaging files locally at any time:

```bash
# Using a local SHA256SUMS file:
bash scripts/update-packaging.sh --version 0.1.6 --checksums dist-bin/SHA256SUMS --out build/packaging

# Using a directory containing release tarballs:
bash scripts/update-packaging.sh --version 0.1.6 --checksums dist-bin/ --out build/packaging

# Downloading checksums directly from a published GitHub release:
bash scripts/update-packaging.sh --version 0.1.6 --out build/packaging
```

The script performs validation:
- Checks that all 6 target SHA-256 sums are accounted for.
- Fails loudly on unknown targets or malformed checksums.
- Verifies that no unreplaced `@@...@@` placeholders remain.
- Generates a valid `.SRCINFO` (using `makepkg --printsrcinfo` if installed, or an identical fallback).
